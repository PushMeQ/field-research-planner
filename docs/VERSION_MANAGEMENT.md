# 版本管理系统设计

## 概述

田野调查行程规划系统采用语义化版本管理，支持大版本（Major）和小版本（Minor）的区分，确保每次变更都有完整记录。

## 版本号规则

### 语义化版本（Semantic Versioning）

格式：`主版本号.次版本号.修订号`（如 `1.2.3`）

- **主版本号（Major）**：重大变更，如：
  - 新增或删除点位
  - 调整路线顺序
  - 变更交通方式
  - 修改每日行程安排

- **次版本号（Minor）**：次要变更，如：
  - 修改点位详情（名称、地址）
  - 更新住宿信息
  - 调整停留时间
  - 添加备注信息

- **修订号（Patch）**：微小变更，如：
  - 修复数据错误
  - 更新联系方式
  - 调整格式

### 版本判断规则

```javascript
// 版本判断逻辑
function determineVersion(changes) {
  // 主版本变更
  if (changes.pointsAdded || changes.pointsRemoved || changes.routeChanged) {
    return 'major';
  }

  // 次版本变更
  if (changes.detailsUpdated || changes.hotelsUpdated || changes.scheduleAdjusted) {
    return 'minor';
  }

  // 修订版本变更
  return 'patch';
}
```

## API 设计

### 1. 创建项目

**POST** `/api/projects`

```json
{
  "name": "甘肃古戏台调查",
  "province": "甘肃省",
  "team": ["PushMeQ"]
}
```

### 2. 创建版本

**POST** `/api/projects/:projectId/versions`

```json
{
  "changes": {
    "type": "major",
    "description": "新增 5 个考察点位",
    "pointsAdded": 5,
    "pointsRemoved": 0,
    "routeChanged": true
  },
  "data": {
    "points": [...],
    "route": {...}
  }
}
```

### 3. 获取版本列表

**GET** `/api/projects/:projectId/versions`

### 4. 获取特定版本

**GET** `/api/projects/:projectId/versions/:version`

### 5. 记录实际行程

**POST** `/api/projects/:projectId/actual`

```json
{
  "day": 1,
  "date": "2026-06-01",
  "pointsVisited": [
    {
      "pointId": 1,
      "arrivalTime": "09:00",
      "departureTime": "10:30",
      "notes": "保存完好，有清代碑刻"
    }
  ],
  "totalDistance": 185,
  "totalHours": 8
}
```

### 6. 生成总结报告

**POST** `/api/projects/:projectId/summary`

## 技术要点

### 1. 版本存储优化
- 使用 Git-like 的增量存储
- 只保存变更部分，减少存储空间
- 支持版本回滚

### 2. 实时同步
- 使用 WebSocket 实现实时更新
- 支持多人协作
- 自动冲突解决

### 3. 数据验证
- 版本号格式验证
- 变更内容完整性检查
- 数据一致性验证

## 注意事项

1. **版本命名规范**：严格遵循语义化版本规则
2. **变更日志完整**：每次变更都要记录详细原因
3. **数据备份**：定期备份项目数据
4. **权限控制**：不同角色有不同的操作权限
5. **审计追踪**：记录所有操作的时间、用户和内容
