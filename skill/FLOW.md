# 田野调查行程规划 Skill - 完整流程

## 概述

通过对话式交互，帮助用户完成田野调查的完整行程规划，最终生成交互式网页。

## 依赖 Skill

本 Skill 依赖以下已启用的 skill：

### 核心依赖
1. **ui-ux-pro-max** - UI/UX 设计规范，确保表格和界面美观
2. **frontend-design** - 创建高质量前端界面
3. **design-html** - 生成生产级 HTML/CSS
4. **make-pdf** - 生成 PDF 文档

### 辅助依赖
5. **scrape** - 从网页抓取数据（酒店信息、点位信息等）
6. **browse** - 测试网页和截图
7. **writing-plans** - 创建实现计划
8. **skill-creator** - 创建和优化 skill

### 工具依赖
9. **tools/table_generator.py** - 表格生成器，自动调整列宽

### 第一阶段：项目初始化（对话式）

#### 1.1 问候与信息收集
```
你好！我是田野调查行程规划助手。

让我们一起规划你的田野调查行程。首先，请告诉我：

1. 项目名称（例如：甘肃古戏台调查）
2. 考察省份（例如：甘肃省）
3. 考察主题（例如：古戏台）
4. 出发城市（例如：兰州、太原、西安）
5. 计划天数（例如：10天）
6. 出行人数（例如：4人）
7. 人员构成（例如：2男2女）

请提供这些信息，或者告诉我你已经有了哪些。
```

#### 1.2 确认信息
- 项目名称
- 考察省份
- 考察主题
- **出发城市**（重要！）
- 计划天数
- **出行人数**（重要！影响住宿和车辆安排）
- **人员构成**（重要！影响房间分配）

#### 1.3 人数与车辆确认
根据人数，确认车辆和住宿安排：
```
根据你们[人数]人出行（[男]男[女]女），我建议：

🚗 车辆安排：
- [人数]人需要[车辆数]辆车
- 建议车型：[车型建议]

🏨 住宿安排：
- 需要[房间数]间房
- 房间分配：[分配建议]

这样安排是否合理？
```

#### 1.4 路线建议
根据出发城市，给出合理的路线建议：
- **避免走回头路**
- **从东向西**或**从西向东**的路线
- **环形路线**：出发城市 → 点位 → 返回

```
根据你从[出发城市]出发，我建议以下路线：

方案A：从东向西
[出发城市] → [东部点位] → [中部点位] → [西部点位] → [返回]

方案B：环形路线
[出发城市] → [北部点位] → [西部点位] → [南部点位] → [返回]

你觉得哪个方案更合适？或者你有其他想法？
```

#### ⚠️ 重要原则：信息真实性
**所有信息必须真实，不能编造！**

- **酒店信息**：必须查询真实酒店名称、地址、电话、价格
- **电话号码**：必须是真实电话，不能编造
- **地址信息**：必须是真实地址
- **价格信息**：必须是真实价格

**如果查询不到真实信息：**
- 告诉用户"暂未查询到该酒店信息"
- 建议用户自行查询或预订
- **绝不能编造虚假信息**

#### ⚠️ 重要原则：网页界面设计
**必须使用专业模板！**

**设计要求：**
- 基于甘肃考察项目的成熟方案模板
- 使用 Leaflet.js 地图
- 每日独立的地图显示
- 详细的点位信息、时间安排、酒店信息

**设计特点：**
- 专业的 CSS 样式（渐变背景、卡片式布局）
- 每日独立的地图（可缩放、可点击）
- 详细的点位信息（带标签）
- 时间安排（精确到小时）
- 酒店信息（名称、地址、电话）

**模板位置：**
- 模板文件：`templates/field-research-template.html`
- 原始模板：`projects/gansu-field-research/甘南田野调查完整方案.html`

**使用方法：**
1. 复制模板文件
2. 修改其中的内容（点位、行程、酒店等）
3. 生成新的方案文件

**模板变量：**
- `{{PROJECT_TITLE}}` - 项目标题
- `{{PROJECT_SUBTITLE}}` - 项目副标题
- `{{PROJECT_DATE_RANGE}}` - 日期范围
- `{{TOTAL_DAYS}}` - 总天数
- `{{TOTAL_POINTS}}` - 总点位数
- `{{COVERED_CITIES}}` - 覆盖城市
- `{{TRANSPORT_MODE}}` - 交通方式
- `{{PEOPLE_COUNT}}` - 出行人数
- `{{ACCOMMODATION}}` - 住宿安排
- `{{DAILY_CARDS}}` - 每日行程卡片
- `{{GENERATED_AT}}` - 生成时间

#### 2.3 信息获取（自动，不询问用户）
**自动获取以下信息：**
- **历史背景**：使用 scrape skill 抓取，找不到就留空
- **周边设施**：高德 API 查询停车场、卫生间、餐饮等
- **联系方式**：使用 scrape skill 抓取，找不到就留空
- **现场照片**：使用 scrape skill 抓取，找不到就跳过
- **酒店信息**：高德 API 查询真实酒店名称、地址、电话、价格

**数据来源：**
- **高德 API**：酒店信息、距离、时间、价格（准确性第一）
- **scrape skill**：历史背景、联系方式、周边设施（补充信息）
- **用户输入**：点位信息、行程偏好

**原则：找得到就找，找不到就算了，不询问用户。准确性第一！**
