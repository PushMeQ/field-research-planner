# 田野调查行程规划 Skill

## 功能描述
为田野调查（如古戏台考察）生成详细的行程规划，包括：
- **行程规划**：路线图、每日安排、考察点详情
- **版本管理**：记录每次变更，支持版本回溯
- **动态更新**：考察途中实时调整，记录实际行程
- **总结汇报**：生成完整的调查报告和统计分析

## 使用方式
- **自动触发**：当用户提到"田野调查"、"行程规划"、"考察路线"等关键词时自动激活
- **手动调用**：在 Claude Code 中输入 `/field-research-plan`

## 工作流程

### 第一步：收集点位信息
询问用户：
1. 提供点位信息（以下任一方式）：
   - **直接粘贴**：将点位信息粘贴到对话中
   - **提供文件路径**：提供本地文件路径（如 `C:\Users\...\点位.xlsx`），Claude Code 会自动读取文件内容
   - **网页端导入**：在网页端使用"批量导入"功能，支持选择文件或直接粘贴
2. 考察省份/地区

#### 支持的文件格式
- **Excel (.xlsx, .xls)**：自动识别"名称"和"地址"列
- **CSV (.csv)**：第一行为表头，包含"名称"和"地址"列
- **文本 (.txt, .md)**：每行一个点位，名称和地址用制表符或逗号分隔
- **JSON (.json)**：数组格式，每个对象包含 name 和 address 字段
- **Word (.docx)**：自动识别表格或列表中的点位信息

#### Claude Code 读取文件示例
用户：我有一个点位文件 `C:\Users\78778\Desktop\甘肃古戏台.xlsx`，帮我导入

Claude Code：
1. 读取文件内容
2. 解析点位信息
3. 调用批量导入 API
4. 返回导入结果

### 第二步：确认规划选项
询问用户：
1. 每日行程量：
   - 推荐点位数量（根据距离自动计算）
   - 或用户指定每日点位数量
2. 交通方式：租车 / 公共交通 / 打车
3. 住宿要求：县城 / 市区
4. 酒店标准：经济型 / 舒适型 / 高档型（如华住会、全季及以上）
5. 停留时间：以半小时为单位递增（1h、1.5h、2h...）

### 第三步：数据处理
1. 解析用户提供的点位信息
2. 调用地理编码 API 获取坐标
3. 验证坐标准确性（与用户信息比对）
4. 如有不一致，提示用户确认

### 第四步：路线规划
1. 询问用户是否有指定顺序
   - 有 → 按指定顺序规划
   - 无 → 运行 TSP 算法优化路线
2. 根据交通方式估算时间
3. 根据停留时间计算每日行程
4. 生成每日住宿推荐

### 第五步：生成输出
1. **交互式地图**（HTML）：
   - 显示所有点位和路线
   - 支持点击查看详情
   - 支持拖拽调整顺序
   - 支持添加/删除点位
2. **行程方案**（HTML + PDF）：
   - 整体安排概览
   - 每日详细行程
   - 考察点详情（历史背景、照片、周边设施）
   - 住宿推荐（名称、价格、预订链接）
3. **路线图**（PNG）：
   - 静态路线图，方便分享

### 第六步：版本管理
1. **创建版本**：每次重大变更都创建新版本
   - 主版本：新增/删除点位、调整路线
   - 次版本：更新详情、调整住宿
   - 修订版本：修复错误、更新备注
2. **版本记录**：自动记录变更内容、时间、操作人
3. **版本回溯**：支持查看和恢复历史版本

### 第七步：动态行程更新
1. **实时记录**：考察途中记录实际行程
   - 实际到达时间、离开时间
   - 停留时长、考察情况
   - 遇到的问题和发现
2. **计划对比**：自动对比计划与实际
   - 点位完成情况
   - 时间偏差分析
   - 里程差异统计
3. **自动调整**：根据实际进度调整后续计划
   - 重新规划剩余路线
   - 调整每日点位数量
   - 优化住宿安排

### 第八步：总结与汇报
1. **行程统计**：
   - 总里程、总耗时、点位完成率
   - 每日平均数据
   - 计划 vs 实际对比
2. **改进建议**：
   - 基于数据的优化建议
   - 下次调查的改进方向
3. **最终报告**：
   - 完整的调查总结
   - 统计图表
   - 经验教训

### 第九步：保存和分享
1. 保存所有文件到项目目录
2. 生成项目配置文件（JSON），方便团队共享
3. 提供导出功能（PDF、图片、数据）

## 版本管理规则

### 版本号规则（语义化版本）
- **主版本号（Major）**：重大变更
  - 新增或删除点位
  - 调整路线顺序
  - 变更交通方式
  - 修改每日行程安排
- **次版本号（Minor）**：次要变更
  - 修改点位详情（名称、地址）
  - 更新住宿信息
  - 调整停留时间
  - 添加备注信息
- **修订号（Patch）**：微小变更
  - 修复数据错误
  - 更新联系方式
  - 调整格式

### 版本判断逻辑
```
如果（新增点位 或 删除点位 或 路线变更）→ 主版本
否则如果（更新详情 或 更新住宿 或 调整行程）→ 次版本
否则 → 修订版本
```

## 动态行程更新流程

### 1. 考察途中记录
- 每天晚上回来后，通过对话更新当日行程
- 记录实际到达时间、离开时间、停留时长
- 记录考察情况、发现的问题

### 2. 自动对比分析
- 系统自动对比计划与实际
- 统计点位完成率、时间偏差、里程差异
- 生成对比报告

### 3. 后续计划调整
- 根据实际进度自动调整后续计划
- 重新规划剩余路线
- 优化每日点位数量

### 4. 完整记录保存
- 所有变更都有完整记录
- 支持查看任意一天的详细记录
- 便于后续总结和复盘

## 总结报告内容

### 1. 完成情况
- 计划点位数 vs 实际完成数
- 完成率统计
- 超额/不足分析

### 2. 行程统计
- 总里程、总耗时、总天数
- 每日平均数据
- 计划 vs 实际对比表

### 3. 改进建议
- 基于数据的优化建议
- 每日点位数量调整
- 停留时间优化
- 路线规划改进

### 4. 经验总结
- 成功经验
- 遇到的问题
- 下次改进方向

## 注意事项
1. 地理编码需要联网，离线时使用缓存数据
2. 住宿价格可能过期，建议出行前再次确认
3. 路线规划仅供参考，实际路况可能有变化
4. 建议提前下载离线地图，以备户外使用
5. 每天考察结束后及时记录实际行程
6. 定期创建版本，保存重要变更
7. 调查结束后生成总结报告，便于复盘

## API Key 配置
首次使用需要配置高德地图 API Key：
1. 访问 https://lbs.amap.com/
2. 注册账号并创建应用
3. 获取 API Key
4. 在项目目录的 `.env` 文件中配置：`AMAP_API_KEY=your_key`
