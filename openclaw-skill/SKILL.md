# 田野调查行程规划 Skill

## 功能描述

为田野调查（如古戏台考察）生成详细的行程规划，包括：
- **行程规划**：交互式路线图、每日行程安排、考察点详情
- **版本管理**：记录每次变更，支持版本回溯
- **动态更新**：考察途中实时调整，记录实际行程
- **总结汇报**：生成完整的调查报告和统计分析
- **多格式输出**：HTML、PDF、PNG

## 使用方式

### 自动触发

当用户提到以下关键词时，Skill 会自动激活：
- 田野调查
- 行程规划
- 考察路线
- 古戏台
- 田野作业
- 调查点位
- 考察点

### 手动调用

```
/field-research-plan
```

## 工作流程

### 第一阶段：项目初始化

#### 1.1 问候与引导
```
你好！我是田野调查行程规划助手。

让我们一起规划你的田野调查行程。首先，请告诉我：

1. 项目名称（例如：甘肃古戏台调查）
2. 考察省份（例如：甘肃省）
3. 考察主题（例如：古戏台）

请提供这些信息，或者告诉我你已经有了哪些。
```

#### 1.2 收集项目信息
根据用户提供的信息，确认：
- 项目名称
- 考察省份
- 考察主题
- 考察时间（如果用户提到）

### 第二阶段：点位信息收集

#### 2.1 询问点位来源
```

1. 直接粘贴点位列表
   格式：名称,地址（每行一个）

2. 提供本地文件路径

3. 提供关键词，我来帮你搜索
   例如：甘肃省古戏台列表

请选择（1/2/3），或者直接粘贴点位信息。
```

#### 2.2 解析与确认
收到点位信息后：
1. 解析点位列表
2. 调用地理编码 API 获取坐标
3. 显示解析结果，请用户确认

```

对于每个点位，询问：
```

1. 历史背景（例如：始建于清代，省级文物保护单位）
2. 现场照片（如果有）
3. 周边设施（停车场、卫生间、餐饮等）
4. 联系方式（如果需要预约参观）

```

```

```

2. 是否需要安排用餐？（我可以推荐当地特色）

```

3. 混合规划 - 我先智能规划，你再调整

## 环境要求

- **Node.js**：版本 16 或更高
- **npm**：随 Node.js 安装
- **高德地图 API Key**：用于地理编码和路线规划

## API Key 配置

首次使用需要配置高德地图 API Key。

### 获取 API Key

1. 访问 https://lbs.amap.com/
2. 注册/登录账号
3. 进入"控制台" → "应用管理" → "我的应用"
4. 创建新应用，选择"Web 服务"类型
5. 复制 API Key

### 配置方式（选择一种）

#### 方式一：永久配置（推荐）

**macOS/Linux（Bash）：**
```bash
echo 'export AMAP_API_KEY=your_key_here' >> ~/.bashrc
source ~/.bashrc
```

**macOS/Linux（Zsh）：**
```bash
echo 'export AMAP_API_KEY=your_key_here' >> ~/.zshrc
source ~/.zshrc
```

**Windows（PowerShell）：**
```powershell
[System.Environment]::SetEnvironmentVariable('AMAP_API_KEY', 'your_key_here', 'User')
$env:AMAP_API_KEY = 'your_key_here'
```

#### 方式二：临时配置（仅当前对话有效）
```bash
export AMAP_API_KEY=your_key_here
```

**注意：** 推荐使用永久配置，这样每次开启新对话时都会自动加载 API Key。

## 离线支持

- **自动缓存**：所有 API 调用结果自动缓存
- **离线模式**：无网时使用缓存数据
- **热点模式**：手机热点也能用
- **预加载**：出发前在家联网使用一次

## 版本管理规则

### 版本号规则（语义化版本）
- **主版本号（Major）**：重大变更
  - 新增或删除点位
  - 调整路线顺序
  - 变更交通方式
  - 修改每日行程安排
- **次版本号（Minor）**：次要变更
  - 修改点位详情（名称、地址）
  - 更新住宿信息
  - 调整停留时间
  - 添加备注信息
- **修订号（Patch）**：微小变更
  - 修复数据错误
  - 更新联系方式
  - 调整格式

### 版本判断逻辑
```
如果（新增点位 或 删除点位 或 路线变更）→ 主版本
否则如果（更新详情 或 更新住宿 或 调整行程）→ 次版本
否则 → 修订版本
```

## 动态行程更新流程

### 1. 考察途中记录
- 每天晚上回来后，通过对话更新当日行程
- 记录实际到达时间、离开时间、停留时长
- 记录考察情况、发现的问题

### 2. 自动对比分析
- 系统自动对比计划与实际
- 统计点位完成率、时间偏差、里程差异
- 生成对比报告

### 3. 后续计划调整
- 根据实际进度自动调整后续计划
- 重新规划剩余路线
- 优化每日点位数量

### 4. 完整记录保存
- 所有变更都有完整记录
- 支持查看任意一天的详细记录
- 便于后续总结和复盘

## 总结报告内容

### 1. 完成情况
- 计划点位数 vs 实际完成数
- 完成率统计
- 超额/不足分析

### 2. 行程统计
- 总里程、总耗时、总天数
- 每日平均数据
- 计划 vs 实际对比表

### 3. 改进建议
- 基于数据的优化建议
- 每日点位数量调整
- 停留时间优化
- 路线规划改进

### 4. 经验总结
- 成功经验
- 遇到的问题
- 下次改进方向

## 注意事项

1. 地理编码需要联网，离线时使用缓存数据
2. 住宿价格可能过期，建议出行前再次确认
3. 路线规划仅供参考，实际路况可能有变化
4. 建议提前下载离线地图，以备户外使用
5. 每天考察结束后及时记录实际行程
6. 定期创建版本，保存重要变更
7. 调查结束后生成总结报告，便于复盘
